# Glossary

Key terms and concepts used in Synapse DB documentation.

## A

**API (Application Programming Interface)**
: The set of functions and methods exposed by Synapse DB for developers to interact with the database.

## B

**Benchmark**
: Performance tests that measure the speed and efficiency of database operations.

**Buffer**
: Temporary storage area in memory used for I/O operations.

## C

**Cache**
: Fast storage layer that keeps frequently accessed data in memory for quick retrieval.

**Cargo**
: Rust's package manager and build tool.

**Commit**
: A transaction operation that saves changes permanently to the database.

**Concurrency**
: The ability to handle multiple operations simultaneously.

**Conventional Commits**
: A specification for commit message format used in Synapse DB development.

**Crate**
: A Rust package or library. Synapse DB is distributed as a crate.

## D

**Database**
: An organized collection of structured data.

**Dependency**
: External library or package that Synapse DB relies on.

## E

**Engine**
: See Query Engine.

**Error Handling**
: The process of managing and responding to errors in code.

## G

**Git**
: Version control system used for Synapse DB development.

**GitHub Actions**
: CI/CD platform used to automate testing, building, and deployment.

## I

**Index**
: Data structure that improves the speed of data retrieval operations.

**I/O (Input/Output)**
: Operations that read from or write to storage.

## L

**Lifetime**
: Rust's mechanism for ensuring references are valid.

## M

**mdBook**
: Tool used to generate this documentation from Markdown files.

**Memory Safety**
: Guarantee that programs don't have undefined behavior related to memory access.

**MIT License**
: Open-source license used by Synapse DB.

## O

**Optimization**
: Process of improving query or code performance.

**Ownership**
: Rust's system for managing memory without garbage collection.

## P

**Parser**
: Component that analyzes and interprets SQL queries.

**Persistence**
: Storing data permanently to disk.

**Pipeline**
: Automated CI/CD workflow for testing and deployment.

## Q

**Query**
: Request for data or information from the database.

**Query Engine**
: Component responsible for processing and executing queries.

**Query Optimization**
: Process of improving query execution performance.

## R

**RAII (Resource Acquisition Is Initialization)**
: C++ principle adopted by Rust for automatic resource management.

**Rollback**
: Undoing changes made during a transaction.

**Rust**
: Systems programming language used to build Synapse DB.

**Rustfmt**
: Official Rust code formatter.

## S

**SQL (Structured Query Language)**
: Standard language for interacting with databases.

**Storage Layer**
: Component responsible for data persistence and retrieval.

**Struct**
: Rust's custom data type for grouping related data.

## T

**Transaction**
: Sequence of database operations treated as a single unit.

**Trait**
: Rust's way of defining shared behavior (similar to interfaces).

**Type Safety**
: Guarantee that operations on data respect the data's type.

## U

**Unit Test**
: Test that verifies a small piece of code in isolation.

## W

**Workflow**
: Automated process defined in GitHub Actions for CI/CD.

## Z

**Zero-Cost Abstraction**
: High-level programming constructs that compile to code as efficient as hand-written low-level code.
